# Make a feature

Use when the admin asks for something new or different in the app: a component, a screen, a change to an existing page, or a new field, filter, card or flow.

1. Pin down the surface: which role sees it, which screen or route, web or mobile app, and what is there today. Ask for a screenshot when none is attached.
2. Walk through the behaviour step by step: what the user clicks, what appears, the empty, loading and error states, and what gets saved.
3. Name the data: which records, fields and statuses are read or written. When unsure, list it as an open question instead of inventing endpoints.
4. Note the design cues the images give: layout, colours, and existing components it should match.
5. Write the Training brief with Type "component" or "screen".

The brief is read later by a developer agent that builds it in the web app, the backend or the mobile app, so keep it concrete enough that the agent needs nothing else from the conversation.
